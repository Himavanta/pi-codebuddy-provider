# 代码规范与重构

日期：2026-10-12
基线：commit `dbbef9d`（初始提交）
验证：`vp test`（11 文件 / 147 测试）、`vp check`（0 error）、LSP 诊断

## 规范

1. 使用统一类型封装模块
2. 不要使用 `for` 循环，使用 `for-in` 或 `for-of` 代替
3. 函数参数超过 3 个时使用对象解构传递
4. 数组元素读取尽量用解构（`[first, second] = dataArray`），不用下标
5. 函数体有效代码行 ≤30，最多 ≤50（注释与空行不计）
6. 完成后用 LSP 检查类型 + `vp check --fix` 检查代码

### 统计口径

- **有效代码行**：去掉注释行与空行后的行数。
- **外层函数不计入嵌套函数**：如 `createAuthFetch` 里定义的 `doRequest` 单独计，
  避免父函数被嵌套实现重复计长。
- **解构风格**：未使用的占位变量用下划线前缀标明语义，如 `[_full, _prefix, word]`。
