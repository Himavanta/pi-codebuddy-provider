### 错误文案用上游 `displayMsg` / `displayTips`

新增 `src/upstream-error.ts`，解析上游结构化错误体：

```json
{
  "code": 11151,
  "msg": "a message has empty content …",
  "displayMsg": { "en": "…", "zh": "存在空白消息，请补全后重试", "zh-hant": "…" },
  "displayTips": { "zh": "对话里有内容为空的消息，模型无法处理。请补全内容，或新建任务重新发送。" },
  "actions": ["NEW_CONVERSATION", "SUBMIT_FEEDBACK"]
}
```

按 `zh → zh-hant → en` 取第一个非空文案，主文案用 `displayMsg`，附 `displayTips`
作可操作建议。`12403`（客户端标识被拒）另加内置提示。

**变化**（同一错误，用户所见）：

| 之前                                                                       | 现在                                                                                                                                    |
| -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `400 {"code":11151,"msg":"a message has empty content…","displayMsg":{…}}` | `codebuddy: 存在空白消息，请补全后重试（上游错误码 11151）`<br>`对话里有内容为空的消息，模型无法处理。请补全内容，或新建任务重新发送。` |

### 429 识别额度耗尽

`14018 Credits exhausted` 之前只按 `Retry-After` 判终态，不带该头时会被当成
普通限流重试。现在用计费类词表（参考 Magpie 的 `brokeWords` 与 Pi 自身的
`NON_RETRYABLE_PROVIDER_LIMIT_ERROR_PATTERN`）识别，**即使带 `Retry-After`
也当场终止**，因为等下去不会变得可用。

只收计费类词（`insufficient_quota` / `credits exhausted` / `余额不足` 等），
短时限流（`rate limit` / `too many requests`）仍交给重试。

### 401 的 HTML 响应体

网关前置代理在凭据无效时返回 HTML 而非 JSON，之前会原样透传给用户。
现在识别为「非结构化」并给出简短说明：

```
codebuddy: 上游 401 返回 HTML 而非 JSON（可能是网关或代理拒绝）——检查凭据或稍后重试
```

### 发现失败的原因区分

`fetchRemoteModels` 之前对失败 `return []`，与「发现成功但模型数为 0」无法区分，
且原因被 `DiscoveryCache` 吞掉。现在：

- 新增 `DiscoveryError`（带 `status` 与 `upstreamCode`），所有失败一律抛出
- `DiscoveryCache` 新增 `onFailure` 回调，降级原因透出到日志
- 日志区分认证失败与一般失败，并带上游错误码与文案

**过程中发现一个真实问题**：凭据无效时上游返回 **HTTP 200 / `code: 0`**，
但 `data` 的形状不同（`data.agent` 而非 `data.agents`，且 `models: null`）。
旧代码会据此返回 `[DEFAULT_MODEL]`，把「只有 auto」当成发现结果。
现在识别为失败并降级。
