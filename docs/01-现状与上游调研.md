## 6. 已核实的 pi-ai 契约（对修复有决定性影响）

来源：`@earendil-works/pi-ai/dist`（随 pi-coding-agent 安装）。

### 6.1 `compat` 由 `provider` / `baseUrl` 自动探测

`api/openai-completions.js::detectCompat()` 只依据 `provider` 与 `baseUrl` 判定，
CodeBuddy 的 `copilot.tencent.com` 不命中任何特例，因此落到默认值：
`supportsDeveloperRole: true`、`maxTokensField: "max_completion_tokens"`、`supportsStore: true`。
这正是必须显式写 `compat.supportsDeveloperRole: false` 的原因。

已实测：`max_completion_tokens`、`store: false` 网关均接受（HTTP 200）；
`role: "developer"` 被拒（HTTP 400 `code 11128`）。

### 6.2 `thinkingLevelMap` 的语义

`types.d.ts`：

```ts
export type ThinkingLevel = 'minimal' | 'low' | 'medium' | 'high' | 'xhigh' | 'max'
export type ModelThinkingLevel = 'off' | ThinkingLevel
export type ThinkingLevelMap = Partial<Record<ModelThinkingLevel, string | null>>
```

`models.js::getSupportedThinkingLevels()`：

```js
const EXTENDED_THINKING_LEVELS = ['off', 'minimal', 'low', 'medium', 'high', 'xhigh', 'max']
return EXTENDED_THINKING_LEVELS.filter((level) => {
  const mapped = model.thinkingLevelMap?.[level]
  if (mapped === null) return false // null 显式标记不支持
  if (level === 'xhigh' || level === 'max') return mapped !== undefined
  return true
})
```

要点：

- pi 的档位是**固定集合**；`thinkingLevelMap` 是「pi 档位 → 上游取值」的映射，**不是可用档位枚举**
- 键必须是 `off|minimal|low|medium|high|xhigh|max`；上游档名作键可能成为死键
- `xhigh` / `max` 必须在 map 中有条目才可见，否则被过滤
- `null` 值 = 显式标记该档不支持
- 不存在 `default` 键（pi 版现用 `thinkingLevelMap.default = effort` 是无效写法）

### 6.3 `reasoning_content` 补空已有原生开关

`api/openai-completions.js:1047`：

```js
if (
  compat.requiresReasoningContentOnAssistantMessages &&
  model.reasoning &&
  assistantMsg.reasoning_content === undefined
) {
  assistantMsg.reasoning_content = ''
}
```

即 `compat.requiresReasoningContentOnAssistantMessages` 可直接替代 opencode 的手工 body 注入。
注意它依赖 `model.reasoning` 为真。
